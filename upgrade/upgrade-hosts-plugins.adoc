= 升级 SnapCenter 插件和主机
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
您可以从 SnapCenter 升级 SnapCenter 插件，也可以仅升级主机上的 Java、.NET 或 PowerShell 组件，而无需更改插件版本。选择适合您环境的选项，并在开始之前将主机置于维护模式。

|===
| 选项 | 使用场合 | 是否手动停止并启动服务？ 


| 从 SnapCenter 升级插件 | 您可以使用 SnapCenter 用户界面升级插件。 | 否，SnapCenter 停止并启动服务。 


| 仅组件升级 | 您仅更改 Java、.NET 或 PowerShell（例如，为了解决 CVE）。插件版本保持不变。 | 是的。您必须停止并启动服务。 
|===

NOTE: 请保留已安装的旧版 Java、.NET 和 PowerShell 版本，直到您验证主机在使用新版本时运行正常。



[[plug-in-upgrade-from-snapcenter]]
== 从 SnapCenter 升级插件

.步骤
. 将所有受影响的主机置于维护模式。
. 在插件升级之前准备好必要条件（并排安装；暂不删除旧版本）：
+
.. Java 17 — 将 `JAVA_HOME`设置为 Java 17；验证命令 `java -version`显示版本为 17（在 Windows 上，如果注册表默认值仍为 Java 11，则即使安装了 Java 17，升级也可能会失败。）
.. .NET andPowerShell 根据您的 SnapCenter 版本的要求。


. 从 SnapCenter 升级主机上的插件。
. 在 SnapCenter 中确认主机和服务是否正常。
. 如果主机上没有其他应用程序需要，请卸载旧的 Java、.NET 和 PowerShell 版本。
. 将主机退出维护模式。


[NOTE]
====
* 您无需手动停止 SnapCenter 插件 Loader （SPL）、SnapCenter 插件 Creator （SCC） 或 `PluginCreatorService` 服务，或使用 `pkill`。
* SnapCenter 插件升级会为您停止并启动服务。
* 如果主机准备不正确（例如，错误的 Java 版本或 `JAVA_HOME`），升级可能会失败，或者升级后可能无法启动服务。


====


[[component-only-upgrade-no-plug-in-upgrade]]
== 仅组件升级（无插件升级）

.步骤
. 将所有受影响的主机置于维护模式。
. 停止 SnapCenter 插件服务，如 <<stop-services,在升级前停止服务>> 中所述。
. 如果停止过程未将其清理，则清除过时的进程。
. 安装新的 Java、.NET 和 PowerShell 版本，并根据需要更新配置（例如 set `JAVA_HOME`）。
. 启动 SnapCenter 插件服务，如 <<start-services,升级后启动服务>> 中所述。
. 在 SnapCenter 中确认主机状态和服务。
. 如果主机上没有其他应用程序需要，请卸载旧的 Java、.NET 和 PowerShell 版本。
. 将主机退出维护模式。




[[stop-services-before-the-upgrade]]
[[stop-services]]
=== 在升级前停止服务

在安装新版本的 Java、.NET 或 PowerShell 之前，请先停止主机上的 SnapCenter 插件服务。

.适用于 Linux 和 AIX 主机的步骤
. 在插件主机上运行以下命令：
+
.. `/opt/NetApp/snapcenter/spl/bin/spl stop`
.. `/opt/NetApp/snapcenter/scc/bin/scc stop`


. 通过运行 `ps -ef | grep -i snapcenter`检查剩余的 SnapCenter 进程。
. 如果陈旧进程仍然存在，请运行以下命令：
+
.. `pkill -f scAgent`
.. `pkill -f '/opt/NetApp/snapcenter/spl'`
.. `pkill -f '/opt/NetApp/snapcenter/scc'`


. 再次运行 `ps -ef | grep -i snapcenter`以确认没有剩余的 SnapCenter 进程，然后再继续。


.适用于 Windows 主机的步骤
. 在插件主机上的 PowerShell 中，运行 `Stop-Service -Name PluginCreatorService -Force`。
. 确认服务已停止。
. 请先停止所有剩余的 Java 和代理进程，然后再继续。




[[start-services-after-the-upgrade]]
[[start-services]]
=== 升级后启动服务

在安装和配置新的 Java、.NET 或 PowerShell 版本后，在主机上启动 SnapCenter 插件服务。

.适用于 Linux 和 AIX 主机的步骤
. 在插件主机上运行以下命令：
+
.. `/opt/NetApp/snapcenter/spl/bin/spl start`
.. `/opt/NetApp/snapcenter/scc/bin/scc start`




.适用于 Windows 主机的步骤
. 在插件主机上的 PowerShell 中，运行 `Start-Service -Name PluginCreatorService`。




[[process-checklist]]
== 流程清单

[role="tabbed-block"]
====
.插件升级
--
. 将主机置于维护模式。
. 并排安装必备组件：设置了 `JAVA_HOME`的 Java 17，以及根据需要安装的 .NET 和 PowerShell。
. 从 SnapCenter 升级插件。
. 确认主机和服务运行正常。
. 如果主机上没有其他应用程序需要，请卸载旧的 Java、.NET 和 PowerShell 版本。
. 将主机移出维护模式。


--
.仅组件升级
--
. 将主机置于维护模式。
. 停止服务并清除过时的进程（如果需要，在 Linux 和 AIX 上使用 `pkill`）。
. 安装新的 Java、.NET 和 PowerShell 版本并更新配置。
. 启动服务。
. 确认主机和服务运行正常。
. 如果主机上没有其他应用程序需要，请卸载旧的 Java、.NET 和 PowerShell 版本。
. 将主机移出维护模式。


--
====
[NOTE]
====
* 要使用的 .NET 和 PowerShell 版本在最新的 link:https://library.netapp.com/ecm/ecm_download_file/ECMLP3359467["SnapCenter 发行说明"^] 中指定。
* 对于插件升级，请使用目标 SnapCenter 版本支持的 Java 版本。对于仅组件升级，请使用已安装版本支持的 Java 版本。SnapCenter 6.2.1 及更高版本需要 Java 17；SnapCenter 6.2 及更低版本需要 Java 11。
* 如果您的站点安装路径与 `/opt/NetApp/snapcenter`不同，请使用您的站点安装路径。
